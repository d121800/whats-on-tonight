# 《今晚播什麼？》手稿文字整理

整理日期：2026-10-19。來源：17 張手寫規劃圖片，頁碼以檔名尾端 1～17 為準，不代表實際遊戲流程順序。

本文件記錄手稿與使用者補充，不擅自補上玩法。標記「待辨識」代表字跡／圖示尚無法確定；「待確認」代表內容可讀，但規則或用途尚未寫清楚。草圖上的示例數字不視為正式參數。

## 一、已確認設定

- 教學角色：阿邁小精靈（不是阿萬小精靈）。
- 難度：普通、瓦哈；瓦哈標為極困難。
- 每天早上固定去醫院上班，晚上 19:00 到家。原稿「早上要去看醫生」的讀法作廢。

## 二、整合規劃

### 遊戲基本設定

- 名稱：《今晚播什麼？》。
- 網頁遊戲，支援 RWD。
- 使用 localStorage 記錄本機資料；手稿另有下載／上傳紀錄的註記。
- 遊戲共七天，3/22～3/28；最後一天為生日直播。
- 教學不占遊戲天數，由阿邁小精靈引導，搭配「咪咪咪」。
- 難度有普通、瓦哈（極困難）。兩者數值差異尚未列明。
- 結束後有數值結算、CG、填寫名字與生日留言、製作名單、回首頁。

### 首頁、首次進入與導覽

- 首頁有標題、Start、Setting。
- 下方有「關於」「成就」「生日」入口。
- 草圖使用藍、橘、黑色作為色彩註記，未列色碼。
- 第一次開啟有訊息／對話式畫面，接著進入房間與教學演出；包含角色在電腦旁、畫面變暗／聚焦螢幕的示意。
- 教學註記「可 skip」。跳過的精確範圍尚未寫明。
- 草圖有「加準備」註記，完整意思待確認。

### 日常房間

- 顯示目前天數、日期、時間、直播預告及體力。
- 第一天示例：3/22，晚上 20:00 直播，旁有「怕」字註記；具體對應後續處理。
- 房間以電腦桌為中心，含螢幕、主機、杯子與角色／動物裝飾。
- 日常畫面記有體力 100；這與各日睡眠、上班扣體力如何銜接需確認，不能一律解讀成每天到家固定 100。
- 活動依已確認設定記錄：吸貓固定 30 分鐘，出門隨機 1～3 小時，通常與動物夥伴同行。其他活動對應後續處理。
- 底部圖示包含對話／終端形狀、貓形、手機與齒輪；各按鈕功能未全部註明。
- 手機分為社群及 Line 類功能。社群使用 Bear 字樣；Line 草圖另以「賴」字表示。
- 社群有頭像／作者、貼文文字、圖片的列表。
- Line 有群組／對話列表，進入後顯示聊天泡泡；聊天可「約出來」，再進入雙人見面事件畫面。
- 群組名稱疑似「大家都在」，成員及名稱需確認。

### 體力、睡眠與活動

- 體力上限為 100；恢復體力不超過此上限。

| 條件／活動 | 體力結果 | 時間／規則 |
|---|---|---|
| 00:00 睡覺 | 恢復後體力 100% | 睡覺時間決定恢復後的體力 |
| 01:00 睡覺 | 恢復後體力 90% | 同上 |
| 02:00 睡覺 | 恢復後體力 75% | 同上 |
| 03:00 睡覺 | 恢復後體力 60% | 同上 |
| 上班 | 固定扣 20% | 每天到醫院上班，19:00 到家 |
| 吸貓 | 隨機恢復 10～30% | 耗時固定 30 分鐘 |
| 出門 | 恢復 25～40% | 耗時隨機 1～3 小時；回復量也隨機，但受出門時間影響，時間決定回復多寡；通常邀遊戲中的動物夥伴一起出門 |
| 體力 ≤ 0 | 觸發累倒跳日事件 | 以文字敘述阿萬太累、翹班並睡了一整天，也睡過直播；不是一般睡眠結算 |

- 出門時間與回復量的具體對應、隨機分布留待後續處理；不假設兩者獨立抽取。
- 吸貓每日最多成功兩次；第三次貓咪會不耐煩並拒絕，這次被拒絕的嘗試不耗時。
- 可以繼續直播到很晚，但會耗體力，晚睡也會使隔天體力不佳。
- 基本上凌晨 03:00 會要求睡覺；是否為不可拒絕的強制操作尚未說明。
- 若在凌晨 03:00 前體力已歸零（≤ 0），優先觸發累倒跳日事件：跳過當天，改用文字敘述太累而翹班、睡整天並睡過直播。
- 累倒跳日依當次晚間活動所屬日判定，不以午夜後的日曆日期切換。3/23 晚上的活動即使跨到 3/24 凌晨，仍屬同一個活動時段。
- 在 3/23 晚上體力歸零，或同次活動跨至 3/24 凌晨才歸零，結果相同：從累倒時睡起，睡過 3/24 整天，錯過 3/24 的上班與直播，進入 3/25。
- 實作時需分開記錄「活動所屬日」與「目前時鐘日期」，避免午夜前後累倒造成不同跳日結果。
- 跳日後的具體時間及恢復後體力尚未說明，不自行推定。


### 直播準備與類型

- 點電腦進入開播設定。
- 自填直播名稱／標題。
- 選擇直播 type。
- 選擇朋友／參與者；圖示包括狗、貓、海豹狀角色、幽靈、雞等，實際角色名稱與可選人數待確認。
- 開播前草圖有「不選人」的劃線圓形圖示，是否表示可單人直播待確認。
- 預計直播時數 1～4 小時，按開始進入直播。
- 一天可以直播多次，沒有每天只能開播一次的限制。
- 不必固定在晚上 20:00 開播，可自行選擇開播時間；第一天畫面上的 20:00 不構成強制規則。
- 正式直播主題共六種：動作遊戲、戀愛遊戲、恐怖遊戲、衛教、雜談、多人遊戲。
- 主題、圖示、動物夥伴、參與條件及數值的對應留待後續處理。

### 直播中與結束

- 直播畫面左側為阿萬與內容，右側為聊天室，下方有標題與日期／人數資訊。
- 畫面有 Live 紅點與「廟中」圓形標誌（字樣待辨識）。
- 角色前方可同時出現多位動物朋友。
- 第 14 張示例畫面含「前き夢」之類的標題／板面字樣，僅保留為待辨識，不視為定案。
- 日常體力上限 100。壓力條只在直播過程中出現，影響直播結束結算時扣除的體力；壓力與扣體力的換算公式留待後續決定。
- 壓力條不是已確認的跨日常駐數值；每場初始值與重置規則尚未說明，不自行設定。
- 每次直播實際執行一分鐘內容；遊戲內預計直播時數為 1～4 小時，與實際操作時間分開。
- 直播中有三種氣氛表情：激動／興奮、平淡、開心。
- 可下指令：控場、炒熱、衛教。手稿對應控場「+壓」、炒熱「++壓」、衛教「-壓」。實際增減量未列。
- 結束畫面有新增數值、人數增加、壓力、體力變化，阿萬評價對話及 End 按鈕。
- 結算例圖含 short +2、訂閱人 +1…、壓力 50、體力 -… 等；部分劃掉／模糊，只能當示意，不能當正式計算公式。
- 第 12 張體力歸零的舊草圖以「體力 ≤ 0 觸發累倒跳日事件」為準。
- 第 12 張另有簡化彈窗「+…／-力／OK」，需確認與完整版結算的關係。
- 第 4 張有「留言 → 文本 → 可刪留言」註記；可刪的留言類型及操作角色待確認。

### 成就

- 手稿中的名稱與進度條僅保留為草案參考，不視為完整清單或定案規則。

### 第七天與結局

1. 第七天生日直播必定觸發，生日直播當天直接將體力補滿至 100；畫面有生日蛋糕、動物朋友、阿萬及聊天室。
2. 生日直播後結算數值。
3. 顯示 CG。
4. 填寫名字與生日留言（name、birth msg）。
5. 跑製作表／製作名單，可 skip。
6. 回到主頁。

- 生日直播當天體力直接 MAX（100），生日直播必定觸發。若前一天的累倒跳日原本會略過生日當天，仍須銜接生日流程，不能取消生日直播；具體轉場尚未說明。
- 當天補滿不代表已確認直播中無敵或體力鎖定，後續是否照常扣體力尚未另行說明。
- 第 1 張與第 16 張流程大致一致；「結算結果」與「CG」畫面之間有箭頭連接。
- 下載紀錄、上傳紀錄已寫入功能想法，但檔案格式、保存哪些資料與入口位置未定。

## 三、資料庫與 API 草案（暫不處理命名）

DB 資料名稱先不處理，以下只保留手稿草案作記錄，不要求現階段核對名稱或調整架構。不代表已實作。原稿使用 nvarchar 型別，實際資料庫型別尚需實作時另行對應。

### 資料表

| 表名 | 欄位／內容 | 備註 |
|---|---|---|
| DB_starttime | createtime | 遊戲開始時間 |
| DB_birthmsg | id、name、msg、isOk | id：int 自動；name：nvarchar(40)；msg：nvarchar(200)；isOk 預設 false |
| DB_txt | id、type、msg | id 自動；type 下有 100、200；msg 看似 nvarchar(200)，長度待確認；type 有 index 註記 |
| DB_setting | type、name、value | 框內註記 exceptType／Live tree／800／預設數…等，字義與對應待辨識 |

### API

1. 開始時間記入：寫入 createtime。
2. 取得直播留言：
   - input：type（分類圖示）、who（角色圖示）。
   - 第三個 input 被劃掉，不納入確定欄位。
   - response（原稿 back）：id、msg、type、remark。
   - type／remark 下有「可 null」註記，指向範圍待確認。
3. 寫入留言：
   - input：name、msg。
   - 寫入 create time。
   - response：isSuccess。
4. 「初次實…〈alert〉信…文字」：首次提示的完整文案與觸發條件待辨識。

留言流程另有「可刪留言」與 isOk 預設 false 的設計；是否代表人工審核後公開，手稿沒有明說，不能直接定案。
